The problem

This draws on two related builds: a multi-algorithm Anomaly Detection Accelerator with automated root-cause analysis over time-series data (Tiger Analytics), and a configurable, correlation-based fraud-detection platform for payroll data (Globant) — the closer match to “correlated, multivariate signals,” since payroll components naturally move together and a component that breaks that correlation is the actual fraud signal. On the payroll platform specifically, the existing approach flagged each payroll component against its own static threshold, which fired constantly on normal correlated movement and cost analyst time chasing false alarms while eroding trust in the system. The goal was to keep recall on genuine fraud while sharply cutting that false-positive rate.

import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
t = np.arange(200)
sig = np.sin(t / 9) + 0.4 * np.sin(t / 3) + rng.normal(0, 0.15, 200)
anom = np.array([40, 96, 150, 178])
sig[anom] += np.array([1.8, -1.6, 2.0, -1.7])

BG, FG, MUTED, GRID = "#0e1016", "#f4f5f7", "#9aa3b2", "#22262f"

fig, ax = plt.subplots(figsize=(8, 4.2))
fig.patch.set_facecolor(BG); ax.set_facecolor(BG)
ax.plot(t, sig, color=MUTED, lw=1.3)
ax.scatter(anom, sig[anom], color="#f87171", s=42, zorder=3,
           edgecolors=BG, lw=0.8, label="detected anomaly")
ax.legend(frameon=False, labelcolor=FG)
ax.set_xlabel("time", color=MUTED); ax.set_ylabel("signal", color=MUTED)
ax.tick_params(colors=MUTED)
for s in ["top", "right"]: ax.spines[s].set_visible(False)
ax.spines["left"].set_color(GRID); ax.spines["bottom"].set_color(GRID)
ax.grid(axis="y", color=GRID, lw=1)
plt.tight_layout()
fig.savefig("hero.png", dpi=120, bbox_inches="tight", facecolor=BG)
plt.show()

The win was modeling the correlation between signals, so normal joint movement stopped tripping single-variable thresholds.

Decisions and tradeoffs

I moved from per-signal thresholding toward a multivariate approach that models the joint distribution, so a change is only anomalous relative to how the signals usually move together. Concretely, this meant PySpark modules that score correlation between payroll components rather than flagging each component against its own static threshold — the platform behind it was built config-driven and multi-algorithm on purpose, so it could plug into a new client’s front-end/back-end stack with minimal manual intervention rather than a rebuild per client.
